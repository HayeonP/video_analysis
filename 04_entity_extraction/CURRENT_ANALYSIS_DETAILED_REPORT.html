현재 기존 뷰어의 기준 결과 sintel_release_validation_20261014를 만든 linked 분석 경로를 설명합니다. 앞으로 만들 빠른 버전의 설계와 섞지 않습니다. 작성 기준일은 2026-10-14입니다.

Adaptive sampling까지는 이미 알고 계시므로, 선택된 사진이 04에 들어온 이후에 집중합니다. 핵심은 “사진 속 무엇이 있는가”, “다른 사진에서도 같은 대상인가”, “한 사진에서 실제 몸은 몇 개인가”를 따로 해결한다는 것입니다.

예전 구조 그림에 있던 Qwen 4B·OSNet·SSIM이 그대로 돌아가는 것은 아닙니다. 현재 sampled 경로는 YOLO11x, DINOv2-small, Qwen3-VL-8B 두 종류를 사용합니다. YuNet/SFace는 선택적 얼굴 보조 정보입니다. OSNet·BoT-SORT·SAM은 이 실행 경로에서 사용하지 않습니다.

초록색은 검출·수치 계산 중심, 보라색은 Qwen이 이미지를 보고 판단하는 단계입니다. 화살표마다 저장되는 데이터가 달라집니다.

1단계 · 중학생도 이해할 수 있는 설명

사진 앨범에서 같은 사람을 찾아 이름표 붙이기

여행 사진 279장을 받았다고 생각해 봅시다. 같은 친구가 앞모습·뒷모습·작은 모습으로 찍혀 있습니다. 컴퓨터는 처음부터 그 친구가 누구인지 모릅니다.

  1. 찾는 담당자(YOLO)가 “여기 사람, 저기 동물” 하고 네모를 그립니다. 사람이라는 것은 알지만, 다른 사진의 사람과 같은 사람인지는 모릅니다.
  2. 외형 메모 담당자(DINO)가 네모 안의 모습을 숫자 메모로 바꿉니다. 메모가 비슷하고 위치도 이어지면, 가까운 사진끼리 같은 임시 번호를 줍니다. 이것이 트랙입니다.
  3. 샷 안의 정리 담당자(Qwen Instruct)가 장면과 확대 사진을 봅니다. “이 손과 저 몸은 한 사람”, “사람이 안고 있는 동물은 별개”를 구분하고 샷 안의 이름표를 붙입니다.
  4. 앨범 전체의 정리 담당자(Qwen Thinking)가 다른 샷의 후보 두 묶음을 비교합니다. 같은 사람이라고 확인하면 하나의 전역 이름표로 합칩니다.
  5. 오류 검사 담당자가 잘못 섞인 외형과 한 장면의 몸 개수를 다시 봅니다. 다른 두 사람이 하나로 합쳐졌으면 분리하고, 한 사람의 몸과 팔을 따로 셌으면 묶습니다.
  6. 설명 담당자(Qwen Instruct)가 통일된 이름표로 장면 설명을 정리합니다. 마지막으로 프로그램이 목록과 박스를 저장하고 뷰어가 보여 줍니다.

가장 중요한 세 가지 구분

사람이라는 분류와 누구인지 나타내는 ID는 다릅니다. 두 사람 모두 person이어도 서로 다른 ID입니다. 또 화면에 보이는 레이블은 사람이 읽는 짧은 설명일 뿐, ID 그 자체가 아닙니다.

예를 들어 서로 다른 샷의 shot_0005:L01과 shot_0012:L01을 같은 사람으로 판단하면 둘 다 G0001을 가리킵니다. 레이블은 “붉은 머리 여성”처럼 붙입니다. L01이라는 숫자가 같아서 합치는 것이 아닙니다.

“네모가 두 개”가 곧 “사람이 두 명”은 아닙니다. 한 사람의 몸 전체와 상반신을 각각 검출했을 수도 있습니다. 반대로 겹쳐 보이는 두 사람이 실제로는 서로 다른 사람일 수도 있습니다.

왜 DINO가 있는데 Qwen도 필요한가요?

DINO는 외형이 비슷한 사진을 찾는 데 유용합니다. 하지만 같은 옷을 입은 두 사람, 배경이 비슷한 두 사진도 비슷하다고 볼 수 있습니다. 따라서 DINO의 점수는 “비교해 볼 후보”이지 동일인이라는 확정 증거가 아닙니다. Qwen은 여러 모습과 장면 문맥을 함께 보고 얼굴·신체·물건·몸의 연결을 설명합니다. Qwen도 틀릴 수 있으므로 응답을 코드로 검사합니다.

왜 Qwen을 두 종류나 쓰나요?

Instruct는 샷 안의 목록, 외형 설명, 첫 번째 몸 구분, 요약처럼 비교적 직접적인 시각 질문을 처리합니다. Thinking은 어려운 샷 간 동일성 비교와 위험한 ID 변경을 다시 확인합니다. 둘 다 여기서는 8B 모델이며, 모델 가중치를 실행 중 새로 학습시키지 않습니다.

병합은 한 번으로 끝나지 않습니다

먼저 샷별 이름표를 만들고, 다음에 샷 사이 이름표를 합칩니다. 그 뒤 연결된 그룹 안에서 모순을 찾습니다. 예를 들어 한 그룹의 여러 사진은 머리카락 있는 여성인데 일부 추적 구간만 대머리 남성으로 확인되면, 그 구간만 분리합니다. 얼굴이 안 보인다는 이유만으로 이미 맞게 연결된 나머지 사진을 모두 분해하지는 않습니다.

같은 프레임 검사는 왜 따로 하나요?

시간을 따라가며 만든 트랙이 싸움 장면에서 상대방으로 옮겨 붙을 수 있습니다. 이 경우 트랙 전체에 같은 ID를 붙이면 오류가 남습니다. 그래서 문제가 의심되는 원본 선택 프레임의 박스들을 함께 보고, 관측 단위로 소유자를 다시 배정합니다. 실제 한 몸에 해당하는 여러 박스는 최종 화면에서 하나의 외곽 박스로 합칩니다.

YOLO/DINO는 선택된 프레임의 검출을 처리하지만, Qwen은 매 프레임마다 전체 파이프라인을 돌지 않습니다. 대표 crop·장면 모음·문제 프레임으로 구성된 비교 자료를 여러 번 받습니다. 샘플링으로 사진 수를 줄여도, 같은 사진으로 Qwen 질문을 많이 하면 느립니다.

3단계 · 컴공 학부생 수준: 실제 실행 흐름

진입점은 analyze_sintel.sh → video_shortcuts.py → benchmark_video.py → run.sh → story_pipeline.py입니다. benchmark는 02 샷 분할, 03 샘플링, 04 분석을 별도 프로세스로 실행하고 단계 시간을 기록합니다. 아래는 기준 실행의 analysis_frames=sampled, global_strategy=linked, global_initialization=local, skip_mask_refinement=true 경로입니다.

selected JPEG + samples.json
  → sampled tracking
  → provisional temporal segmentation
  → local semantic review
  → singleton local groups → focused global reconciliation
  → target-specific appearance profiles
  → observation-level physical identity repair
  → narrative revision
  → export + structural/identity validation

파일명에 dense_tracking이 남아 있어도 실행 모드가 sampled이면 선택 JPEG만 읽습니다. 디렉터리 이름으로 처리 범위를 판단하면 안 됩니다.

3.1 · 샘플링 입력 계약과 검출

discover_sampled_shots는 summary와 samples를 읽고 선택 프레임 번호가 정렬·중복 없음, 처음과 끝 프레임 보존, hold 구간이 전체 샷을 덮음, FPS·원본 오프셋·시각 일치, 실제 JPEG 존재를 확인합니다. JPEG 내용 해시도 계산합니다. iter_shot_images는 이 목록의 파일만 읽으며 선택되지 않은 프레임을 요청하면 실패합니다.

YOLO 전체 화면 검출의 입력 크기는 1280, 신뢰도 하한은 0.08, NMS IoU 설정은 0.72입니다. 작은 대상을 보완하려고 640 크기 타일(25% 겹침, 최대 6개)도 검사합니다. 원본 프레임 번호가 6의 배수이거나 현재/직전 관측에 작은 대상이 있으면 타일 검출을 추가합니다. 새 시간 프레임을 읽는 것이 아니라 같은 선택 사진을 나눠 다시 검출하는 것입니다.

타일 좌표는 전체 사진 좌표로 복원하고 중복 검출을 합칩니다. 낮은 신뢰도 검출을 전부 entity로 승격하지 않습니다. 트랙에 연결되지 않은 후보도 별도 회복 증거로 남깁니다.

실측: 선택 프레임 279개에 전체 화면 검출 279회, 추가 타일 검출 1,122회. 검출 후보 1,571개 중 트랙에 속한 관측은 527개, 미연결 저신뢰 후보는 1,044개였습니다. “279장 분석”은 “모든 모델을 합쳐 279회만 실행”이라는 뜻이 아닙니다.

3.2 · DINO 임베딩과 임시 추적

DinoEncoder는 검출 crop을 최대 16개씩 배치 처리합니다. DINOv2-small의 마지막 은닉 상태에서 CLS 토큰을 가져와 L2 정규화하고, 저장할 때 소수점 7자리로 반올림합니다. 정규화 벡터의 내적은 코사인 유사도로 사용할 수 있습니다.

SparseTracker.update는 원본 시각 기준으로 약 1초 넘게 보이지 않은 활성 트랙을 만료시킵니다. 이전 박스와 새 박스의 IoU가 0.3보다 작고 외형 유사도도 0.75보다 작으면 연결 후보에서 제외합니다.

score = 0.65 × max(0, cosine_similarity)
      + 0.35 × box_IoU
      − 0.05 × elapsed_seconds / track_buffer_seconds
cost  = 1 − score

score ≥ 0.45인 후보에 대해 Hungarian 알고리즘으로 일대일 배정합니다. 외형 벡터가 없을 때는 IoU ≥ 0.5 조건을 사용합니다. 새 트랙은 별도 신뢰도 조건을 충족해야 시작합니다(전체 화면 기본 0.40, 타일 출생 기준 0.60). 중간에 관측하지 않은 프레임의 박스를 예측해 만들지 않습니다.

대표 사진은 한 트랙의 전체 관측 중 일부를 선정하며 기본 상한은 8개입니다. 샷 문맥 사진도 기본 10개를 고릅니다. 선택 이미지, 원본 bbox, crop, feature, source time, track ID가 다음 단계의 증거가 됩니다.

3.3 · 트랙이 다른 사람으로 넘어갔는지 검사

split_temporal_tracks는 CPU에서 이미 계산한 외형 벡터와 박스를 분석합니다. 새 Qwen 호출이나 dense 추론이 아닙니다. 같은 트랙의 앞부분과 뒷부분이 갑자기 다르면 잠정 구간으로 나눕니다. 내부 화면 전환과 장시간 누적된 추적 드리프트도 검사합니다.

예를 들어 관측 간격이 0.5초를 넘고 외형 유사도가 0.65 미만인 경우, 또는 외형 유사도 0.50 미만이면서 IoU 0.20 미만인 경우를 의심합니다. 이 밖에 앞뒤 관측 창의 안정성, 평균 외형, 길이가 긴 트랙의 양 끝 변화도 확인합니다. 세부 기본값은 아래 설정 표와 소스에 있습니다.

이 분리는 “다른 인물 확정”이 아니라 “별도로 보여 주고 다시 판단할 구간”입니다. 원시 관측을 빠짐없이 나누며, 나중에 같은 사람으로 다시 연결할 수 있습니다.

3.4 · Qwen Instruct가 샷 안에서 하는 일

각 샷마다 전체 장면 사진 모음, 트랙별 여러 crop, 같은 장면에서 대상들의 관계가 보이는 확대 이미지를 만듭니다. 모델에는 T001 같은 짧은 별칭과 관측 범위·개수도 줍니다.

모델은 트랙마다 무엇이 보이는지 설명하고, 역할을 whole_subject / body_part / handled_object / worn_item / background / uncertain로 분류합니다. 모든 트랙을 Local ID 또는 reject에 정확히 배정하고, 인물·동물·물체 종류, 요약, 사건, 관계를 반환합니다. 손은 소유한 몸에 연결할 수 있지만 손에 든 도구나 안고 있는 동물은 별도 entity입니다.

JSON 스키마와 별도 검증 함수가 ID 누락·중복·발명, 잘못된 프레임과 시간 등을 검사합니다. 의심되는 로컬 병합은 audit_local_identity, 검출기와 의미 분류가 충돌하는 대상은 audit_local_classification으로 추가 확인합니다. 각 감사의 기본 추가 생성 상한은 4회입니다. 이 실행에서는 분류 감사가 실제 2회 사용됐습니다.

검출 트랙이 없는 샷도 이미지 요약은 할 수 있으나, 없는 ID나 박스는 만들지 않습니다. 샷별 검토가 실패하면 불완전한 전체 결과를 완료로 승격하지 않습니다. 실제 기준 실행에서는 17샷의 로컬 단계가 재시도 포함 18회 생성, 추가 분류 2회였습니다.

3.5 · 샷 사이 병합: 후보 검색, 모델 판단, 그래프 갱신

A. 초기 상태

global_initialization=local이므로 처음부터 영화 전체의 정답 목록을 주지 않습니다. 로컬 entity 33개가 각각 별도 가설로 출발합니다. C0001 등은 이 단계의 작업용 그룹 번호이고, 최종 G0001과는 구분됩니다.

B. 비교 후보를 만드는 방법

DINO 다중 시점 벡터 간 유사도 행렬에서 상위 최대 3개 점수의 평균으로 후보를 순위화합니다. 기본 상위 후보에 같은 종류의 온전한 대상 후보도 보충합니다. 선택적으로 YuNet으로 crop의 얼굴 위치·선명도를 확인하고 SFace 벡터를 만들어 후보를 보충합니다. 얼굴이 없으면 이 보조 경로는 건너뜁니다. 얼굴 근거는 여러 관측이 있어야 후보 생성에 사용됩니다.

인접 샷 경계의 관측 연속성, 외형 설명의 단어 겹침, 이미 검토한 쌍, 객체의 역할, 명시적 분리 관계도 후보 순위와 제외에 반영됩니다. 고립된 손 같은 부분 대상은 다른 샷의 몸과 무작정 비교하지 않고 같은 장면의 소유자 후보를 우선합니다.

C. Qwen에 실제로 주는 질문

현재 코드는 신뢰도를 위해 한 번에 후보 한 쌍으로 좁힙니다. 양쪽 그룹의 대표 시점들을 고르고, 필요한 경우 얼굴 detail 또는 같은 프레임의 두 몸이 보이는 증거를 제시합니다. 질문은 “같은 대상인가, 다른 대상인가, 판단 불가인가”이며, 어느 Local ID의 어느 프레임에서 어떤 특징을 확인했는지 요구합니다.

Thinking은 먼저 생각 과정 1,024토큰으로 제한합니다. 검증 후에도 미확정인 샷 간 비교에 한해 같은 입력 이미지·질문으로 긴 추론을 한 번 더 요청합니다. 긴 요청은 보통 전체 응답 상한 8,192토큰입니다. 첫 번째 비교의 생각 예산, 최종 JSON 길이, 실제 생성 횟수는 서로 다른 개념입니다.

D. 모델이 same이라고 하면 바로 합치나요?

아닙니다. normalize_review가 제시된 ID·프레임 근거인지, 역할상 가능한 관계인지 등을 검증합니다. apply_review는 부정 근거를 먼저 등록하고, 병합할 두 그룹의 모든 구성원 사이에 금지 관계가 없는지 검사합니다. A=B, B=C라는 답만 보고 A와 C의 알려진 충돌을 무시하지 않습니다.

같은 샷의 같은 프레임에서 별도 몸임이 확인된 근거는 강한 cannot-link로 다룹니다. 외형 차이 같은 부정 근거는 재검토 가능한 이의로 관리합니다. 같은 옷·종류·이름 하나만으로 합치지 않으며 미확정은 미확정으로 남깁니다. 병합할 때 더 긴 설명을 자동 대표 이름으로 고르지 않습니다.

E. 종료와 이력

후보 소진 또는 생성 예산에서 멈춥니다. 이 실행의 전역 비교 상한은 재시도 포함 96회이며 재개해도 누적 상한이 초기화되지 않습니다. 실제로 64개 검토 요청에 96회 생성을 사용했습니다. 로컬 33개 가설이 전역 11개 그룹으로 줄었지만, 이것은 아직 외형·몸 보정 전입니다. 질문·응답·병합·미해결 후보·스냅샷을 저장합니다.

3.6 · 잘못된 외형·레이블·프레임별 몸을 보정

A. 외형 프로필: 연결과 이름을 분리

build_profile_cache는 외형이 급변한 의심 트랙의 구간별 crop을 준비합니다. Instruct는 각 구간을 독립적으로 보고 머리카락/대머리, 얼굴 털, 시각적 외형, 혼합 여부를 기록합니다(추가 상한 4회). 이름이나 영화 줄거리로 인물을 맞히라고 하지 않습니다. 숨겨진 속성은 unknown입니다.

이 프로필은 원본 샷·프레임·bbox와 crop의 실제 바이트 해시에 연결됩니다. 그룹 안에서 여러 샷이 지지하는 외형을 기준으로, 검증된 대상별 모순이 있는 구간만 분리합니다. 보이지 않는 얼굴을 반대 증거처럼 취급하지 않습니다. 레이블은 이 외형 프로필로 따로 선택합니다. 이 과정에서 대머리 남성이 여성의 이름을 덮어쓰는 문제를 방지합니다.

B. 어떤 프레임을 다시 보나요?

동일 ID에 공간적으로 다른 박스가 붙었거나, 서로 다른 외형이 섞였던 샷의 관측을 선택합니다. 기준 실행에서는 39프레임입니다. 사진 위의 D1, D2…는 그 프레임의 검출이고, 아래 G0001… 사진은 다른 시점의 참조 인물입니다. 참조 사진을 그 장면에 있는 추가 사람으로 세면 안 됩니다.

C. 두 번의 검토와 조건부 세 번째 질문

먼저 Instruct가 검출들을 실제 몸 단위로 나누고 G ID를 대응시킵니다. 기존 ID 변경이나 겹침이 약한 온전한 몸의 병합처럼 중요한 판단은 Thinking이 독립적으로 재확인합니다. 전경 몸의 중앙을 보고, 박스 가장자리에 비친 상대방 얼굴을 그 몸의 주인으로 착각하지 않도록 묻습니다. 모델을 프레임마다 바꾸지 않고 저렴한 1차 검토를 모아서 끝낸 뒤 강한 검토를 모아 실행합니다.

여전히 새로운 미확정 사람이 생기는 경우에는 참조 인물 사진을 빼고 원본 장면의 해당 영역을 확대해 몸 개수만 다시 묻습니다. 몸에 붙은 팔·상반신은 소유자와 묶고, 확인된 그림자·반사·배경은 별도 독립 대상에서 제외할 수 있습니다. 동물에게 이 사람 전용 몸 해석을 강제로 적용하지 않습니다.

매 검출 D가 정확히 한 번 배정됐는지, 같은 G를 두 몸에 중복 배정하지 않았는지, 설명과 배열이 모순되지 않는지 검사합니다. 오류 응답은 제한된 재시도로 교정하며 해결하지 못하면 성공으로 처리하지 않습니다. 기준 실행은 1차/형식 재시도 46회와 Thinking 28회, 합계 74회 생성입니다.

D. 결과를 데이터에 적용

트랙 전체가 아니라 (shot, frame, bbox) 관측 키 단위로 G를 수정합니다. 한 트랙이 서로 다른 인물을 포함하면 관측을 새 트랙/Local ID로 나누어 재배정합니다. 원시 관측은 삭제하지 않습니다. 같은 몸이라고 확인한 박스들의 정확한 프레임·원본 트랙·bbox를 physical_groups에 증거로 남깁니다.

실제 그림자 회귀 사례는 그림자 픽셀을 제거한 것이 아닙니다. 그림자 관측이 소유자의 ID와 함께 남아 별도 사람 ID가 되지 않았습니다. 거울을 통한 동일인의 중복 표현은 현재 지원 범위 밖입니다.

3.7 · 장면 설명과 최종 뷰어

Global ID를 정한 뒤 Instruct가 최대 4샷씩 묶어 장면 설명과 사건을 다시 검토합니다. 해당 샷에 관측되지 않은 entity를 사건 주체로 쓰거나 시간 범위를 벗어나면 거절합니다. 보정 실패 시 기존 로컬 설명에 전역 ID를 치환한 결과로 남기고 품질 경고를 기록합니다. 현재 결과의 5개 배치에는 재시도 포함 7회 생성이 들었고, 2개 배치의 6샷은 의미 보정에 실패했습니다.

export_story는 실제 관측과 ID 매핑으로 등장 목록을 만듭니다. 검증된 physical_groups와 정확히 일치하는 관측들만 먼저 하나의 외곽 bbox로 통합합니다. 다음으로 같은 ID의 높은 겹침 박스를 중복 억제합니다(기본 IoU 0.70 또는 작은 박스 기준 포함률 0.95). 나머지 동일 프레임 동일 ID 중복은 검증 오류입니다. 한 개만 보이게 만들려고 임의의 다른 사람 박스를 버리는 방식은 아닙니다.

샘플링 영상은 선택 사진과 그 사진의 박스를 다음 선택 시각까지 유지합니다. 원본의 모든 프레임에 새 추적 박스를 그리는 동영상이 아닙니다. 실제 출력은 279장의 선택 사진으로 52.208초 재생 길이를 맞춥니다. 현재 결과에는 오디오가 없습니다.

구조 검증은 모든 트랙이 배정/거절되었는지, 관측 없는 entity나 대표 사진 누락, ID 참조 오류, 프레임·시각·영상 길이, 한 프레임 동일 ID 충돌을 검사합니다. 구조가 맞는다는 것은 모든 사람의 정체를 맞혔다는 뜻은 아닙니다. 독립적인 정답 관측 평가가 별도로 필요합니다.

6 · Sintel 전용인가요? 새 영상·새 캐시에서는?

분석 코드에는 Sintel 등장인물 이름, 정답 ID, 특정 샷 번호를 기준으로 병합하는 규칙이 없습니다. 현재 실행의 외부 context는 빈 객체입니다. 영화 소개문이나 과거 정답 인물 목록 없이 새 분석 캐시에서 만들었습니다. Sintel/Frozen 이름은 입력 파일을 고르는 실행 편의 스크립트에 있고, Sintel 정답 관측은 평가 파일에만 있습니다.

범용 로직이라는 것과 어떤 영상에서도 같은 정확도를 보장한다는 것은 다릅니다. 실사·애니메이션·군중·동물·어두운 영상은 검출 난도와 외형 변화가 다릅니다. 거울, 외형이 거의 같은 여러 인물, 매우 짧은 등장, 작은 대상, 가림은 어려울 수 있습니다. 불확실한 대상을 억지로 하나로 합치면 정확도가 아니라 오병합이 늘어납니다.

캐시는 이미지·모델·질문·설정 등으로 검증된 응답 재사용을 위한 것입니다. 빈 출력 경로로 실행하면 새 분석을 합니다. 모델 가중치 재사용과 인물 분석 캐시 재사용은 다릅니다. GPU 수치 연산과 모델 생성 특성 때문에 실행마다 모든 JSON이 바이트 단위로 같다고 약속할 수는 없으며, 비교 평가는 실제 관측의 동일성 기준으로 해야 합니다.

8 · 다음 속도 개선 실험과 비교 방법

기존 기준 결과를 보존하고 새 버전은 별도로 만듭니다. 목표는 샷별 추출 이후의 전역 인물 통합·몸 보정을 실제 생성 5~10회로 제한하는 것입니다. 로컬 검토와 요약까지 전체 Qwen 호출을 10회로 만들었다는 뜻은 아니며, 최종적으로 전체 시간도 함께 비교합니다.

개선 실험에서는 한 쌍씩 묻는 대신 여러 후보·프레임을 한 번에 검토하는 방식을 시험합니다. 정확도 확인 전에는 기존 결과와 동등하다고 표시하지 않습니다. 부분 정답의 기존 올바른 연결 유지, 오병합, 같은 프레임 중복, 원시 관측 보존을 모두 비교합니다.
