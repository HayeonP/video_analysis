# 04 방법 슬라이드

13장 · SVG 개념도 · 분석 결과나 정확도 측정값을 표시하는 자료가 아닙니다.

## 01. 여러 샷의 관측을, 같은 대상끼리 연결합니다

네 단계만 기억하세요: 관측을 정리하고 → 외형으로 연결하고 → 문맥으로 검토하고 → 기록합니다.

<p>현재 run.sh의 Qwen ON 경로를 설명합니다. YOLO 검출·특징 추출, 중복 정리, 외형 기반 기본 목록, 제한된 Qwen 검토, 결과 저장 순서입니다.</p><p>그림의 인물·생물·ID·개수는 개념 예시입니다. 특정 영화나 정해진 등장인물 수를 규칙으로 사용하지 않습니다. 수정 후 실제 동일성 정확도는 아직 확인하지 않았습니다.</p>

## 02. 박스 → 트랙 → Entity: 세 가지 단위

검출 횟수와 실제 대상의 수를 구분합니다.

<p>관측은 선택 프레임 하나의 검출 박스입니다. 트랙은 한 샷 안에서 이어진 관측 묶음이고, Entity는 샷을 넘나드는 동일성 추정입니다.</p><p>T…는 샷 내부 트랙, V…는 외형 연결로 만든 기본 ID이며 출력 시 E… 형식의 최종 ID로 정리됩니다. 번호는 의미나 인물 수를 미리 정하는 규칙이 아닙니다.</p>

## 03. 시간은 유지하고, 선택된 이미지만 분석합니다

04는 03의 샘플 시각을 이어받습니다. 생략된 원본 순간을 다시 분석하지 않습니다.

<p>summary.json과 샷별 samples.json에서 source_frame, hold_until_frame, 원본 시각을 읽습니다. adaptive 영상의 디코딩 프레임과 메타데이터의 시각이 맞는지 확인합니다.</p><p>선택 이미지 A를 다음 선택 이미지 B까지 유지합니다. 표시 시간이 길어도 같은 이미지를 매 원본 프레임마다 다시 분석하지 않습니다. 그림의 시각·간격은 설명용입니다.</p>

## 04. 전체 화면을 보고, 작은 대상을 확대합니다

검출 단계의 목표는 “무엇이 어디에 보이는가?”입니다.

<p>기본 모델은 YOLO11x, 입력 크기 1280, 사람·물체 신뢰도 기준 0.25입니다. 작은 사람이 관측된 샷이거나 해당 프레임에서 사람을 찾지 못하면 타일 검출을 시도합니다.</p><p>프레임당 최대 6개 타일을 사용하며, 타일에서 추가하는 대상의 높이는 전체 화면 높이의 9% 이하입니다. 전체 화면 검출에는 이 높이 제한이 없습니다. 검출할 확대 클래스는 설정으로 변경할 수 있습니다.</p><p>Qwen은 이 경로에서 새로운 박스를 추가하거나 좌표를 수정하지 않습니다. YOLO가 끝내 찾지 못한 대상의 누락은 이후 이름·관계 검토만으로 복구되지 않습니다.</p>

## 05. 외형을, 서로 비교할 수 있는 특징으로 바꿉니다

얼굴이 가려지면 근거가 줄어듭니다. 몸과 전체 외형도 함께 비교합니다.

<p>YuNet으로 얼굴을 찾고, 크기·선명도 등 품질 조건을 만족하면 SFace 특징을 추출합니다. 사람 crop에서는 OSNet-AIN 몸 특징과 DINOv2-small 특징도 구합니다.</p><p>사람이 아닌 대상은 DINO 특징으로 비교합니다. 특징 벡터의 코사인 유사도를 사용하며, 점수는 동일 대상일 확률이 아닙니다. 여러 관측의 좋은 시점과 반복 지지를 함께 반영합니다.</p><p>DINO는 이 구조에서 박스 검출기나 이름 생성기가 아닙니다. 같은 이름이나 같은 검출 클래스 자체도 동일성 근거로 쓰지 않습니다.</p>

## 06. 한 샷 안에서는, 관측을 시간순으로 연결합니다

샷 내부 트랙은 여러 장의 관측을 담는 작은 사진 묶음입니다.

<p>외형, 박스 겹침, 중심 위치, 이전 이동량을 이용한 위치 예측, 실제 시간 간격을 함께 점수화합니다. Hungarian 일대일 할당으로 현재 관측을 이전 트랙에 연결합니다.</p><p>기본적으로 최대 3개 샘플 간격과 2초 이내의 관측을 연결 후보로 둡니다. 애매한 연결은 임시 트랙을 분리해 보존합니다. 이 단계만으로 샷을 넘는 동일성을 결정하지 않습니다.</p><p>그림의 아래 선은 관측 사이의 연결을 표현합니다. 검출하지 않은 중간 프레임에 새 박스를 보간해 만드는 것은 아닙니다.</p>

## 07. 중복 박스는 줄이고, 별개의 대상은 유지합니다

박스가 겹친다는 사실에 외형·크기·반복 관측 근거를 더해 판단합니다.

<p>먼저 임시 샷 내부 트랙에서 여러 프레임의 중복 근거를 확인합니다. 기본적으로 지지 프레임이 2개 이상이고 공통 프레임의 절반 이상이어야 하며, 나머지 공통 관측의 위치·크기와 얼굴 충돌도 확인합니다.</p><p>다음으로 프레임별 중복을 정리하고 깨끗한 트랙을 다시 만듭니다. 같은 프레임의 매우 유사한 박스는 위치·면적·DINO 근거로 서로 다른 검출 클래스 간에도 정리할 수 있습니다.</p><p>융합 시 최고 신뢰도의 실제 관측을 유지합니다. 제거한 검출 ID·대안 클래스·연결 근거는 audit JSON에 남깁니다. 여러 대상을 품은 큰 박스로 합성하지 않습니다.</p>

## 08. Qwen을 부르기 전에, 샷 사이의 기본 연결을 만듭니다

V-ID는 외형으로 구성한 기본 목록입니다. 연결되지 않은 관측은 미확정으로 보존합니다.

<p>트랙당 기본 최대 5개 외형 후보를 골라 강한 연결부터 묶습니다. 얼굴 근거가 복장 유사도에 묻히지 않도록 후보 슬롯 일부를 얼굴 후보에 배정합니다.</p><p>사람 자동 연결은 얼굴 ≥0.55, 또는 얼굴 ≥0.48과 DINO ≥0.50/몸 ≥0.60 중 하나, 또는 몸 ≥0.86과 DINO ≥0.78의 결합 근거를 사용합니다. 비사람은 DINO ≥0.90이 기본입니다. 수치는 설정 가능한 휴리스틱이며 확률이 아닙니다.</p><p>연결 묶음 전체에 대해 실제 동시 등장과 신뢰할 수 있는 얼굴 모순을 확인합니다. 큰 묶음은 대표 모습이나 여러 독립 관측의 지지도 요구합니다. 한 개로 남은 트랙은 새 실제 개체가 확정되었다는 뜻이 아닙니다.</p>

## 09. Qwen은 기존 목록의 의미를 검토합니다

이름을 붙이는 일과 동일 개체를 연결하는 일을 구분합니다.

<p>먼저 외형 연결로 구성한 기존 Entity ID가 있습니다. Qwen은 선택된 전체 장면과 ID별 대표 모습을 보고 짧은 한국어 이름, 종류, 안정적인 외형 설명을 제안합니다.</p><p>이 단계에서도 두 기존 ID의 같음·다름·미확정 관계를 제안할 수 있습니다. 관계 제안은 코드의 외형 근거와 실제 동시 등장 검사에 통과해야 적용됩니다.</p><ul><li>기본 전체 검토: 샷당 장면 프레임 2개, 요청당 최대 40개, 기존 ID 최대 24개.</li><li>한 ID의 대표 crop은 최대 2개이며 가능한 경우 서로 다른 샷의 모습을 사용합니다.</li><li>새 박스나 존재하지 않는 ID를 생성하지 않습니다. 명확한 오검출 제외에는 두 개의 구체적 근거를 요구합니다.</li></ul>

## 10. 시간순으로 관측의 소속을 검토합니다

외형 후보와 앞선 장면의 요약을 함께 주되, 실제 연결은 코드가 확인합니다.

<p>Qwen은 현재 배치의 트랙 crop, 후보 Entity의 대표 모습, 선택 장면 프레임, 기존 배정, 앞선 샷의 요약을 함께 받습니다. 각 트랙을 기존 ID에 연결하거나 미확정으로 두거나 명백한 오검출로 제안할 수 있습니다.</p><p>기본 배치는 4샷 단위이지만 긴 입력에서는 전체 배치 수가 5개를 넘지 않도록 한 묶음의 샷 수가 늘어납니다. 배치당 최대 32개 트랙, 샷당 장면 프레임 4개를 제시하며 요청당 장면 수는 최대 40개입니다.</p><ul><li>외형 후보는 기본 3개이며, 작은 목록에서는 전체 기준 ID를 보여줍니다. 기존 배정도 항상 후보 화면에 포함합니다.</li><li>같은 Qwen 모델을 Python이 정해진 순서로 호출합니다. 여러 자율 agent가 계획하거나 협의하는 구조는 아닙니다.</li><li>박스가 사라졌을 때 Qwen이 다시 검출해 새 박스를 만드는 절차는 현재 없습니다.</li></ul>

## 11. 마지막에는 분리된 ID의 관계를 다시 봅니다

Qwen의 “같다”는 제안이며, 외형과 실제 관측의 충돌 검사를 통과해야 연결됩니다.

<p>최종 검토는 활성 Entity 목록 중 선택된 ID를 대상으로 한 번 수행합니다. Qwen은 전체 선택 장면, 대표 모습, 앞선 요약을 보고 두 ID가 같은 개체인지 제안합니다.</p><p>추가 병합에는 얼굴·몸·DINO의 긍정적 외형 근거가 필요합니다. 실제로 같은 프레임에 나타난 서로 다른 대상은 분리합니다. 다만 중복 검출로 확인된 두 박스는 별개의 대상이라는 충돌 근거로 취급하지 않습니다.</p><ul><li>이름·종류·서사상 역할이 같다는 이유만으로 합치지 않습니다.</li><li>기본 최종 검토 대상은 최대 24개 ID입니다. 모든 미확정 트랙을 다시 개별 배정하는 단계는 아닙니다.</li><li>역방향 순회나 모든 ID 쌍을 반복 호출하는 절차는 없습니다. 얼굴이 가려지거나 외형이 크게 바뀌면 연결이 보류될 수 있습니다.</li></ul>

## 12. 계획은 최대 7개 요청, 실제 생성은 최대 8회

응답 실패로 기본 외형 연결을 버리지 않고, 미완료 검토를 표시합니다.

<p>기본 요청 계획은 전체 목록 검토 1회, 시간순 배치 최대 5회, 마지막 목록 관계 검토 1회입니다. 관측이 없는 묶음은 생략하므로 실제 요청 수는 더 적을 수 있습니다.</p><p>새 Qwen 생성의 절대 상한은 실패·재시도·GPU 메모리 오류를 포함해 작업당 8회입니다. 마지막 검토를 위해 1회를 예약하고, 중단 후 재개할 때도 기존 사용량을 이어 씁니다.</p><ul><li>각 요청 위치에서 재시도는 최대 한 번이며 공통 8회 상한을 넘지 못합니다.</li><li>저장된 요청 캐시를 재사용하면 새 생성 횟수는 늘지 않습니다.</li><li>잘못된 응답 항목은 개별적으로 제외합니다. 응답 실패·예산 소진·검토 누락은 기본 연결을 보존하고 품질 기록에 남깁니다.</li><li>8회 예산으로 임의 길이 영상의 모든 대상을 검토한다는 의미는 아닙니다.</li></ul>

## 13. 목록·등장 행렬·영상으로 결과를 검토합니다

Entity의 대표 모습과 등장 근거를 원본 시간축에서 함께 확인합니다.

<p>출력에는 Entity별 대표 이미지와 짧은 레이블, 샷별 등장 행렬, adaptive 전체 영상의 박스 시각화가 포함됩니다. 비교 모드에서는 ON/OFF 결과와 비교 영상도 저장합니다.</p><p>표의 1은 선택 프레임에서 해당 Entity가 관측되었다는 뜻입니다. 0은 이 분석에서 검출되지 않았다는 뜻이며, 생략된 원본 프레임까지 대상이 없었다고 증명하지는 않습니다.</p><ul><li>원본 시간 정보와 adaptive 프레임의 유지 구간을 보존합니다. 결과 영상은 무음입니다.</li><li>미확정 연결, 검토하지 못한 관측, 호출 예산과 적용·거절 근거도 별도로 기록합니다.</li><li>ON/OFF는 같은 입력과 검출 후보를 사용하지만 외형 연결 알고리즘도 달라 Qwen만 분리한 엄밀한 대조 실험은 아닙니다.</li><li>현재 수정의 실제 정확도는 새 추론 결과로 아직 확인하지 않았습니다. 개체 수가 줄었다는 사실만으로 정확도가 좋아졌다고 판단하지 않습니다.</li></ul>
