  • 외형 특징: 얼굴·몸·물체를 벡터로 표현

박스에 붙는 정보

검출 준비 단계의 Qwen 호출은 아직 전체 이야기 기억을 이용한 동일인 판단이 아닙니다.

09 / REVERSE PASS

마지막 샷에서 빈 기억으로 다시 시작합니다

샷 방문 순서만 반대입니다. 샷 안의 동작은 정상 순서로 재생합니다.
10 / RECONCILIATION

방향별 연결을 다시 확인하고, 남은 중복도 찾습니다

현재 구현은 보수적으로 병합합니다. 동의한 연결도 실제 이미지로 다시 검토합니다.

실제 검토 자료: S005_001 ↔ S008_004 · 같은 여성의 서로 다른 장면

방향별 연결 62건 + 전역 후보 137건
총 199건의 개별 판정 기록
  • 확대 crop + 장면 영상으로 두 대상 재판정
  • same이면 crop만으로 주 대상 재확인
  • 둘 다 same이고 제약에 걸리지 않으면 병합
  • 남은 전체 ID를 페이지 쌍으로 비교해 중복 후보 추가 검색

동시 등장 및 different 판정은 간접 연결을 합칠 때도 제약으로 사용합니다. 잘못된 거절이 실제 같은 대상의 병합을 막을 수도 있습니다.

18 / PROPOSAL B 새 구조 제안 · 아직 미구현

샷 요약과 entity 기억을 함께 추론하는 구조

현재는 샷 요약을 저장하지만, 사건·인물 관계의 누적 기억으로 활용하지 않습니다. 이 지점을 바꿉니다.

01 / OBSERVER

샷 관찰

보이는 대상과 행동·관계를 정리하고, 시각과 crop에 근거를 연결합니다.

관측 + 근거 있는 샷 요약
02 / IDENTITY REASONER

동일성 가설

후보 ID + 가설 + 부족한 증거
03 / EVIDENCE RETRIEVER

추가 증거 검색

얼굴이 보이는 샷, 연결되는 행동, 가림이 풀리는 시점을 다시 찾아옵니다.

비교할 영상·프레임·crop
04 / VERIFIER

검증·기억 갱신

이미지 근거를 검사해 연결·보류·분리를 결정하고, 기존 판단도 수정합니다.

근거가 붙은 ID 변경 이력
역할 이름만 나누는 것으로 충분하지 않습니다. 실제로 추가 증거를 검색하고, 잘못된 과거 판단을 되돌릴 수 있어야 합니다.

이 그림의 agent는 새 분석 프로그램의 역할 설계입니다. 현재 실행에 다중 agent를 사용했다는 뜻이 아닙니다.

19 / EVIDENCE MEMORY 제안 · 미실행

결론만 쌓지 않고, 근거와 가설을 함께 기억합니다

“빨간 머리 여성”이라는 문자열 대신, 왜 같은 사람일 수 있는지와 무엇을 더 확인해야 하는지를 저장합니다.

ENTITY MEMORY — 제안 필드

stable_traits 얼굴·머리·신체의 지속적 특징

changing_traits 옷·조명·자세 등 변화

views 선명한 얼굴 / 전신 / 옆모습

decisions 합침·분리·보류 및 변경 이력

빨간머리 여성 사례의 확인 순서

  • 겨울 복장과 민소매 장면을 동일성 가설로 연결
  • 옷 차이는 변화 특징으로 분리
  • 얼굴·단발 형태가 보이는 추가 장면 검색
  • 동시에 별개 인물로 나오는 반대 증거 확인
  • 충분하면 ID 통합, 부족하면 가설 유지
샷 요약도 모델의 추정입니다. 이야기상 역할만으로 합치지 않으며, 요약의 각 주장에 실제 프레임 근거를 연결해야 합니다.
20 / DESIGN DECISIONS 검토할 변경점

한 번의 오판이 이후 병합을 영구히 막지 않도록

현재의 보수적 병합 규칙에는 장점과 비용이 있습니다. 새 설계에서는 증거 강도와 수정 절차를 명시해야 합니다.

항목현재 구현새 구조에서 검토할 방향

추가 확인미리 정한 crop·장면으로 재판정부족한 정보에 따라 도구로 새 증거 검색
부정 판정최종 병합 과정에서 제약으로 사용강한 반대 증거와 약한 의심을 분리·재평가

비용 관리전체 기억 + 전역 페이지 쌍 검토불확실한 사례 중심의 검색·검토 예산
