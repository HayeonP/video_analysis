1. 먼저 전체 순서

기본 단위는 샷별 개체입니다. 선택 프레임의 박스를 샷 안에서 추적합니다. 샷별 개체를 영상 전체의 ID로 연결합니다. 이후 실제 프레임을 확인해 잘못된 연결을 고칩니다.

예: 샷 1의 여성 A와 샷 5의 여성 B가 같은 사람이면 둘 다 G001을 받습니다. 샷 전체를 한 인물로 취급하지 않습니다. 한 샷에 여러 인물이 있을 수 있습니다.

2. 공통 과정: Step 1–5

순서·담당입력 → 작업 → 출력
1. TransNetV2원본 영상 → 화면 전환 감지 → 샷 경계. 이 단계는 샘플링보다 먼저 실행합니다.
2. Adaptive sampling각 샷 → 영상 변화에 따라 프레임 선택 → 분석할 사진 목록. 이후 04의 이미지 분석은 이 선택 프레임을 사용합니다.
3. YOLO11x선택 사진 → 사람·동물·물체 탐지 → 위치 박스·종류·신뢰도. 작은 대상은 같은 사진의 타일에서도 찾습니다.
4. DINOv2-small + 추적 코드각 박스의 crop → 외형 벡터 생성 → 위치·시간·외형을 이용해 샷 안에서 연결. 한 대상을 따라간 관측 묶음을 트랙이라고 합니다.
5. Qwen3-VL-8B-Instruct장면 사진·트랙 대표 사진 → 외형과 상황 해석 → 샷별 개체와 초기 요약. 이 설명은 모델의 추정이며 정답으로 고정하지 않습니다.

현재 경로에서는 YuNet·SFace·OSNet을 별도로 실행하지 않습니다. 추적·충돌 검사·ID 갱신은 일반 코드입니다. Qwen이 모든 선택 프레임을 매번 읽는 것도 아닙니다. 작업별 대표 이미지와 검토 프레임을 받습니다.

3. 프롬프트는 누가 만드나?

Python이 고정 지시문과 실행 데이터를 조합합니다. 별도의 언어 모델이 다음 질문을 작성하지 않습니다.

재료만드는 주체·예시
고정 지시문개발자가 작성합니다. “왼쪽과 오른쪽 대상이 같은 실제 개체인지 판단하라.” 같은 일반 규칙입니다.
비교할 후보·사진·번호Python이 고릅니다. DINO 유사도, 현재 그룹, 검토 이력 등을 이용합니다. 프레임 번호·시간은 원본 데이터에서 가져옵니다.
외형 설명·초기 요약앞 단계 Qwen이 생성합니다. Python은 필요한 요청에만 이 값을 넣습니다. 설명을 넣지 않는 비교 경로도 있습니다.
JSON 형식·사진 배치Python의 규칙입니다. 응답 스키마와 이미지 라벨도 미리 정의합니다.
같다/다르다/불확실 판단비교 요청을 받은 Qwen이 생성합니다. Python이 형식과 모순을 검사한 뒤 적용합니다.

“자동 생성”의 뜻부터 구분하기

여기서 자동 생성은 Python이 정해진 규칙으로 요청을 조립한다는 뜻입니다. 예를 들어 json.dumps(inventory)는 이미 있는 데이터를 JSON 문자열로 바꿉니다. 문장을 생각해 쓰는 언어 모델 호출이 아닙니다.

앞 단계의 Qwen 호출은 외형 설명과 샷 요약을 만듭니다. 다음 단계의 Qwen 호출은 사진을 비교해 동일성을 판단합니다. 두 호출 사이에서 Python이 후보를 고르고 입력을 연결합니다.

짧은 실행 예시

다음 ID·설명·숫자는 이해를 위한 예시입니다. 실제 Sintel 응답을 복사한 것이 아닙니다.

① 앞 단계 Qwen의 샷별 출력
   샷 1 / A: “붉은 머리, 가죽 옷을 입은 인물”
   샷 5 / B: “옆모습의 인물, 가죽 옷”

② Python의 후보 선택
   A와 B의 대표 이미지가 유사하다.
   아직 검토하지 않은 조합이다.
   → 비교할 두 후보로 선택한다.

③ Python의 요청 조립
   고정 지시문 + 필요한 JSON 데이터 + A/B 사진
   → Qwen 호출

④ 비교 단계 Qwen의 응답
   same / different / uncertain + 시각적 근거

⑤ Python의 적용
   존재하는 ID인가? 근거 프레임이 유효한가?
   서로 다른 몸이라는 확정 증거와 충돌하는가?
   → 검사 후 병합하거나, 분리·미확정 상태를 유지한다.

이전 방식의 일반적인 좌우 사진 비교는 간결한 입력을 사용합니다. 전체 샷 요약을 매번 전달하지 않습니다.

prompt = paired_policy + "\nEVIDENCE: " + json.dumps(compact)
response = request(prompt, PairedViewDecision, images=images)

신체 일부·장면 경계·기타 검토 경로에서는 더 큰 inventory를 사용합니다. 이쪽에는 후보 ID, 외형 설명, 관련 샷 요약, 병합 금지 조합 등이 들어갑니다.

prompt = 선택한_고정_정책 + "\nEVIDENCE: " + json.dumps(inventory)
response = request(prompt, 해당_응답형식, images=images)
“하드코딩”을 구분해야 합니다. 지시문·점수 공식·임계값·출력 형식은 코드에 고정돼 있습니다. 영화의 정답 인물이나 특정 샷의 병합 결과를 고정한 것은 아닙니다. 앞선 설명에서 ‘자동 입력에 요약이 들어간다’고 한 것은 가능한 경로를 설명한 것이며, 모든 비교 요청에 들어간다는 뜻은 아닙니다.

4. 이전 방식: Step 6–9

  1. 후보 쌍을 정렬합니다. 외형 유사도·설명 겹침·장면 경계 연결 등을 사용합니다.
  2. 한 쌍을 자세히 비교합니다. 두 후보의 사진을 Qwen에 보냅니다. 답을 적용한 뒤 다음 조합을 고릅니다.
  3. 외형과 실제 몸을 추가 검수합니다. 잘못된 연결과 중복을 보정합니다.
  4. 요약을 별도로 보정합니다. 최종 ID와 결과 파일을 내보냅니다.

장점은 개별 조합을 자세히 확인할 수 있다는 점입니다. 비용은 비슷한 근거를 반복해서 읽고 답을 생성하는 데서 커집니다.

5. new 방식: Step 6–10

  1. 후보별 사진 카드를 만듭니다. 한 후보에 최대 3개 모습을 넣습니다.
  2. 여러 카드를 함께 비교합니다. Qwen Thinking에 같은 실제 대상끼리 그룹을 나누도록 요청합니다.
  3. 외형과 프레임 검수를 묶습니다. Qwen Instruct로 여러 대상의 특징과 여러 프레임의 몸·ID 대응을 검사합니다.
  4. 불명확한 대상에 문맥을 제공합니다. 시간순 사진·참조 모습·반복 등장·장면 연결로 재판단합니다.
  5. 코드가 최종 모순을 검사합니다. 레이블 근거를 집계하고 ID·한국어 요약을 저장합니다.

대표 사진 카드 제작 순서

먼저 트랙마다 최대 8개 관측을 고릅니다. 대상 크기와 탐지 신뢰도가 좋은 사진, 처음·마지막 사진, 시간·외형이 다른 사진을 포함합니다. 얼굴 선명도를 완벽히 판정하는 모델은 아닙니다.

다음으로 비교 카드에 최대 3장을 넣습니다. 큰 crop을 우선합니다. 합쳐진 그룹에서는 서로 다른 구성원의 모습을 먼저 고릅니다. 구성원이 많으면 처음·마지막·가장 크게 보이는 구성원을 고려합니다.

카드는 300×360 픽셀 크기입니다. 후보 ID와 샷 내부의 원본 프레임 번호를 표시합니다. 예를 들어 f23은 해당 샷의 23번 프레임입니다. 영상 전체 프레임 번호와 원본 시각은 관측 데이터에 별도로 보관합니다. 여러 카드를 별도 이미지로 한 요청에 첨부합니다. 신규 후보 최대 21개와 이전 그룹의 참조 후보 최대 3개를 한 묶음으로 다룹니다.

new 요청의 뜻 — 축약 예시
“첨부한 I001, I002, I003 카드를 같은 실제 대상끼리 묶어라.
병합 금지 조합은 합치지 마라. 이전 외형 설명은 틀릴 수 있다.”

응답 예: {"groups": [["I001", "I003"], ["I002"]]}

new도 Python이 고정 템플릿과 데이터를 조립합니다. 바뀐 것은 질문을 만드는 주체가 아니라 한 질문에서 비교하는 대상의 수와 증거 구성입니다.

③ Qwen이 그룹을 생성한다

실제 첫 응답에서 I001·I005·I006은 서로 다른 임시 그룹에 배정됐습니다. 이 응답이 바로 최종 정답은 아닙니다. 같은 요청에서 작게 보이는 사막 인물을 노인 쪽 그룹에 넣은 판단은 뒤의 프레임 검수와 문맥 재판단에서 수정됐습니다.

질문 텍스트를 조립하는 주체는 Python입니다. 사진을 보고 설명이나 그룹을 생성하는 주체는 Qwen입니다. 앞 단계의 Qwen 설명을 재사용해도, 별도의 모델이 비교 질문 자체를 새로 작성하는 것은 아닙니다.

7. 비슷한 후보를 찾는 예시

DINO는 crop을 외형 벡터로 바꿉니다. 서로 다른 샷의 대표 사진 벡터끼리 코사인 유사도를 계산합니다. 두 개체의 사진 조합 중 높은 점수 최대 3개의 평균을 후보 점수로 씁니다.

A와 비교할 후보상위 사진 유사도 → 평균
B: 비슷한 옷의 옆모습0.91, 0.88, 0.85 → 0.88
C: 비슷한 색 옷의 다른 사람0.84, 0.80, 0.76 → 0.80
D: 외형이 다른 인물0.62, 0.59, 0.56 → 0.59

위 숫자는 설명용입니다. B가 우선 후보입니다. 0.88이 동일인 확률 88%라는 뜻은 아닙니다. 전체 상위 4개와 같은 종류의 온전한 대상 상위 4개를 합쳐 비교 힌트를 만듭니다.

이전은 다른 점수도 더해 다음 비교 쌍을 정합니다. new는 종류별 묶음에 이 후보 관계를 넣고, 이전 그룹의 참조 카드를 고를 때도 사용합니다. new 전체 순서가 유사도 순으로만 정렬되는 것은 아닙니다.

8. 문맥을 추가하는 예시

예 A. 사막에서 작게 보이는 사람

대상 사진만 보면 머리와 나이를 읽기 어렵습니다. 앞부분에서 선명하게 보인 인물 사진을 함께 줍니다. 시간순 장면 사진과 초기 요약도 줍니다. 반복 등장 수와 실제 샷 경계의 연결 증거를 추가합니다.

질문의 뜻
“얼굴이 작으므로 대머리·수염·나이를 추측하지 마라.
반복 등장한 인물과 복장·장비·체형을 먼저 비교하라.
반대 증거가 있으면 분리하라. 근거가 부족하면 uncertain을 허용한다.”

영상 종류는 일반 ‘영화 예고편’ 정보입니다. 특정 인물 이름이나 정답 샷 번호는 넣지 않습니다. 선명한 등장 샷이 최소 3개이고 참조 인물들의 선명한 등장 수 합계에서 60% 이상을 차지하면, 주요 반복 인물 후보로 제안합니다. 빈도는 비교 우선순위의 근거이며 자동 병합 명령이 아닙니다. 문맥으로 연결한 경우 그 추정 근거를 남깁니다.

예 B. 작은 조류처럼 보인 대상과 밝은 피부의 생물

DINO로 비슷한 대상과 시점을 찾습니다. 서로 가장 가까운 후보인지와 다음 후보와의 차이도 검사합니다. 유사한 사진 쌍 최대 3개를 Qwen Instruct에 보냅니다. 날개·몸통 등 신체 구조가 같은 개체로 설명 가능한지 묻습니다.

이때 앞 단계의 장면 전환 종류·연결 근거를 전달합니다. 기존 ‘새’라는 이름과 전체 요약은 전달하지 않습니다. 잘못된 이름이 새 판단을 지배하지 않도록 하기 위해서입니다.

현재 구현은 샷마다 최종 요약을 하나씩 누적하며 재호출하는 방식이 아닙니다. 샷별 초기 분석 후, 시간순 증거를 묶어 인물 재판단과 한국어 요약을 생성합니다. 그중 장면 연결 정보를 후속 동물 판단에 전달합니다.

측정: 같은 Sintel 입력, 새 분석 캐시, 기존 모델 가중치 재사용. 다운로드·설치 제외. 이전 전체 시간은 기록 프로세스 종료 후 시작·종료 시각으로 복구한 값입니다. 속도 수치는 이 52.2초 영상의 저장된 실행 결과입니다. 일반 영상에서 같은 비율을 보장하는 수치는 아닙니다.

지정한 Sintel 관측의 연결·분리 검수에서는 좋은 결과를 얻었습니다. 모든 프레임·모든 영화의 같은 정확도를 보장한 것은 아닙니다. 미확정 동물과 일부 부정확한 행동 요약이 남습니다. 긴 영상·많은 인물에서 10회가 충분한지도 별도로 검증해야 합니다.
